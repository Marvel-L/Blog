## 用户明确要求

1. 按分类创建卡片库；卡片库包含多张 Q & A 卡片。
2. 默认只显示 Q，用户主动操作后才显示 A。
3. 用户自行评价回答情况，支持按评价确定下一次出现时间，或自行指定天数。
4. 每个卡片库展示进度；另提供每日统计及每日进度。
5. 在线录入和查看卡片库；正式数据存数据库，登录用户只能访问自己的数据。
6. 参考 Love 的独立内容空间，从主页点击 Anki 进入专门页面，保留返回路径。
7. 先做 HTML 展示并确认开发方向；子任务进度保存在本地；规则归 ai-rules。
8. v3 依据最新反馈整体重设计：取消侧栏、独立卡片网格、统计小面板；使用统一白色阅读面、顶部导航、连续库列表。轻透明仅用于导航与弹层，不以毛玻璃分块拼接页面。
9. 任何非空卡片库均支持无序随机查看，包括没有到期内容的库；到期练习与随机浏览分开。
10. 每日统计改为简洁折线图；日期记录改为 GitHub 式热力图，格子默认不显示日期或数量，仅悬停/键盘聚焦/手机点击时提示。

## 用户已确认的核心规则（2026-10-26）

以下三项为用户当面确认的承重规则，正式实现必须遵守。本节是对下文「开发前确认项」的正式回答。

1. **调度算法：SM-2 自适应（非完整 FSRS，非完整 Anki 实现）**
   - 官方基准：SuperMemo SM-2（<https://www.super-memory.com/english/ol/sm2.htm>）。本项目按该公式实现，但**仅做三档 UI 映射 + 10 分钟初学步 + 不强制当日复练的适配**，不是 Anki 全量实现，也不是 FSRS。
   - 三档 UI → SM-2 评分映射：「错误」= q=1，「模糊」= q=3，「正确」= q=5。
   - EF 递推：`EF' = max(1.3, EF + 0.1 - (5-q) * (0.08 + (5-q) * 0.02))`；EF 下限 1.3。
   - 成功（q≥3）reps 递推：第 1 次成功间隔 1 天，第 2 次成功间隔 6 天，之后 `interval = ceil(interval_prev * EF_prev)`；连续 correct 序列为 1 → 6 → 17 → 48 天。
   - 失败（q=1）：`EF -= 0.54`、reps 归 0、interval 归 0，并进入 10 分钟额外学习步（下一轮重现）。
   - 默认在揭示答案后隐藏「下次间隔」数值，不向用户预支算法结果。
   - **自定义天数独立**：用户手动指定 N 天属于一次性排期覆盖，独立提交；保留 EF/reps 不变、不递增正确/错误计数，调度上不推断为「正确」或「错误」。但作为一次有效评价事件：`reviewCount += 1`，并按既有去重口径计入当天 unique 卡片数与 reviews 次数（不与三档互评同时入账）。
   - 原型中的「错误 10 分钟 / 模糊 ×1.2 / 正确 ×2.5」仅为原型交互示意；正式实现已按官方 SM-2 公式替换，不得在文档或 UI 中宣称与 Anki/FSRS 算法一致。

2. **自然日与时间口径：Asia/Shanghai 按实际提交时间跨零点**
   - 日统计、连续练习、目标历史快照统一按 Asia/Shanghai 自然日；一张卡片归属哪一天，由服务端收到评价请求的实际时间（UTC 存储）换算到 Asia/Shanghai 后判定。
   - 跨零点会话：23:59 提交归前一天，00:00 之后归当天，以服务端时钟为准，不采信客户端时钟。
   - 客户端时钟不能决定服务端真实调度结果（沿用修改规则 9）。

3. **修改 Q/A 与历史保留：默认保留进度，可选重学，历史不删除**
   - 编辑 Q/A 文本默认保留该卡片既有间隔、dueAt、熟练度状态和历史评价日志；用户须显式选择「重学」才重置排期。
   - 重学是显式动作，不随保存自动触发。
   - 历史评价日志作为不可变记录保留，即使卡片重学或迁库也不删除；迁库后旧日志保留原库归属快照。

## 用户授权边界（本轮确认）

- **入口与布局**：正式入口为 `/anki`（沿用站点既有 basename 配置，禁止硬编码），从主页进入独立学习面，保留返回博客路径。
- **保护面**：不得修改 Love 模式、阅读模式、Pages 与 cloud 既有裁剪能力；不替换 Home、既有账号能力；不擅自启用云端能力。
- **低影响参数沿用原型**：每日目标默认 12 张、可调 1–500；「熟练」= 间隔 ≥21 天的状态标记（仅状态展示，不等于掌握率）；统计图沿用近 7 日折线 + 近 13 周 GitHub 式热力。这些是原型阶段沿用值，正式实现不另起炉灶。
- **范围保护**：暂不新增批量导入、共享卡片库、AI 生成、媒体卡片、排行榜、提醒、部署等用户未要求的能力。

## 修改规则（必须遵守）

1. **正式实现范围**：原型保留在 `anki-prototype/anki.html` 作为历史参考，不删除；正式实现按现有 Go + PostgreSQL + React SSG 边界接入，遵守下文规则。不替换 Home、Love 或既有账号能力。
2. **独立性**：正式版参考 Love 的隔离展示理念，不复用其持久化模式状态、不修改其入口和背景。独立地址 `/anki`、主页入口位置、与 Love/阅读模式的优先级已按上文「用户授权边界」确认。
3. **真实鉴权**：复用项目既有账号能力；只从服务端会话解析身份。所有分类、库、卡片、复习、统计和更新/删除接口必须按会话用户授权。不能信任客户端传入的用户标识，不能仅靠隐藏 UI 隔离数据。
4. **数据库与边界**：按现有 Go + PostgreSQL 边界实现，使用编号 SQL 迁移和事务。不得在生成的静态内容、SSG HTML、公共 JSON、分析日志、Service Worker 缓存中泄露卡片与答案。Pages 与 cloud 的能力边界遵循 `cloud-platform.md`，不擅自启用云端能力。
5. **答案揭示**：练习初始态不在可访问性树中显示 A，自评控件仅在揭示后可用；切下一张自动隐藏答案。列表同样默认收起答案。编辑器展示 A 是录入/修改的明确操作，不记为练习。
6. **调度权威性**：正式版由服务端计算并持久化 dueAt、间隔和算法版本。算法已按官方 SM-2 实现：三档 UI 映射 q=1/q=3/q=5，`EF' = max(1.3, EF + 0.1 - (5-q)*(0.08+(5-q)*0.02))`，成功 reps 1→1 天、2→6 天、之后 `ceil(interval_prev * EF_prev)`；q=1 时 EF-=0.54、reps/interval 归零、10 分钟初学步。本项目为适配版，不是 Anki/FSRS 全实现，不得对外宣称与 Anki/FSRS 一致。自定义排期与自评等级严格区分（见「用户已确认的核心规则」第 1 条）。
7. **原子且幂等的复习记录**：一次评价的记录、卡片调度更新应在同一事务内完成。事务内使用 `clock_timestamp()` 锁定评价时间戳并按 Asia/Shanghai 分桶；重放键含 `cardId / version / rating / custom`，相同重放返回既有结果，不二次入账。处理重复请求、双击和并发标签页，失败不推进下一张，不虚增完成量。未到期的卡片不应混入到期队列；新卡与复习卡可明确区分。
8. **统计口径**：已学覆盖率、熟练/稳定状态、到期数量、当日去重卡片数和评价次数分别展示。未揭示、仅浏览、录入/编辑不能增加练习进度。重复评价不能重复增加同一天不同卡片数。自定义间隔在 SM-2 调度侧不推断为「正确」，但仍计为一次 reviewCount 与当天 unique/reviews 统计（见「用户已确认的核心规则」第 1 条）。目标完成率不等于掌握率。
9. **时间规则**：服务端存 UTC 时间；日统计按 Asia/Shanghai 自然日，以服务端收到评价请求的实际时间跨零点判定（见「用户已确认的核心规则」第 2 条）。客户端时钟不能决定服务端真实调度结果。
10. **录入与安全**：Q/A、分类和库名称校验空白与长度；默认安全文本渲染。如新增 Markdown/富文本须净化并测试 XSS，不接受未经处理的 HTML。保护错误和空数据状态。
11. **SSG/水合与清理**：正式 React 页面遵循 AGENT.md；渲染期不读本地存储、时钟或随机数。账号恢复、请求取消与竞态、退出和账号切换数据清理、监听器与定时器清理按既有模式处理。
12. **无障碍和响应式**：提供可访问名称，弹窗焦点陷阱与关闭后焦点恢复，动态进度播报，点击等价操作。原型与正式版适配桌面和手机。
13. **原型透明边界**：HTML 只演示本机 localStorage 和演示账号；不得描述为安全登录、数据库或跨设备同步。数据读写失败明确反馈，不覆盖损坏原记录，不鼓励保存私密信息。
14. **进度与验收**：长期状态以 `packages/project-notes/features/anki.md` 为准，区分原型、用户确认、代码、自动测试、SQL 隔离测试、真实登录和生产验收。**已通过的部分**：原型 v3 双端核心验证、后端真实隔离 PG `-race` 独验（SM-2 标准、004 迁移、schema 隔离、用户隔离、并发幂等、due 守卫、custom、编辑保留）、前端 desktop fixture 与 9 行为测试、typecheck / 根 `npm test`（140 文件 1097 测试）/ Go 真 SQL / Pages-cloud-server 构建。**未验部分**：真实生产 OAuth、生产库迁移、公网验收、严格 390px 手机复验；未拿到证据前不得勾选为完成。
15. **不扩大范围**：暂不新增批量导入、共享卡片库、AI 生成、媒体卡片、排行榜、提醒、部署等用户未要求的能力。
16. **随机浏览边界**：非空库的随机浏览不依赖 dueAt，包含已学与未学全部卡片；切卡/重洗隐藏 A。此模式默认不自评、不改排期、不新增日志或完成量，不能混入到期练习的调度处理。
17. **统计视觉**：趋势使用简洁折线；热力格默认只显示色阶，不常驻数字或日期。悬停、键盘聚焦与手机点击提示必须使用同一份真实统计，未来日期格不显示；布局按周列/星期行，保留月份和色阶说明。
18. **整体视觉（v3 覆盖 v2）**：清新通透不等于堆叠毛玻璃小面板；默认统一阅读底面、连续库列表、顶部导航，减少大圆角容器、彩色分块和重复边框。只保留问答主体的单张卡片与必要弹层。不得修改原博客全局主题。
19. **折线图质量**：按真实容器宽度确定 viewBox 和坐标，不使用 preserveAspectRatio=none 拉伸圆点与线；数值轴、自然日期轴、零基线和提示共用统计数据。ResizeObserver 重绘须断开旧订阅；窄屏可隔项显示日期，不挤压字体。图表验收不能只检查文件或 SVG 存在。

## 原型示意参数（仅历史参考，非正式 SM-2）

下列数值是原型阶段为交互演示而定的占位参数，**不是正式 SM-2 规则**，不得在生产代码或对外文案中沿用或冒充为算法实现：

- 默认按「错误 / 模糊 / 正确」评价，额外提供「显示下次间隔」开关与自定义整数天数（1–365）。
- 错误：10 分钟后；模糊：`max(1, round((旧间隔 || 1) × 1.2))` 天；正确：`max(3, round((旧间隔 || 1) × 2.5))` 天。仅用于交互示意。
- 从未评价为「未学习」；评价过且间隔不足 21 天为「学习中」；间隔 ≥21 天为「熟练」。这是原型阈值，不是经验证的记忆程度。
- 每日已练按 (本机自然日, 卡片) 去重，评价次数独立累计；目标初值 12 张，可调整为 1–500。
- 每轮开始对当时到期卡片取快照，先复习后新卡；错误卡到期后在下一轮重新加入，不在本轮提前重复。
- 浏览卡片可编辑，编辑保留排期；调整内容后的状态重置策略已按「用户已确认的核心规则」第 3 条确认（默认保留，显式重学）。迁库后旧日志保留原库，作为练习发生时的归属快照。
- 近 7 日折线图与近 13 周 GitHub 式热力图；历史统计示例、今天零起步并随真实原型操作变化。周为列、星期为行，未来格隐藏；固定色阶 0 / 1–3 / 4–6 / 7–9 / 10+ 张；单格默认无文字，提示使用同一份统计数据。
- 非空库有独立「随机浏览」入口，Fisher–Yates 洗牌、单轮不重复，可上一张/下一张/重洗，切卡后隐藏答案。随机浏览不评价、不改变排期、不计入每日进度；到期练习行为保留。
- 演示账号仅一个；退出隐藏学习视图但保留本机数据，不具备多用户隔离安全性。
