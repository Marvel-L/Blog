# 关于页能力雷达 — AI 修改规则

## 授权与交付边界

用户已确认当前玻璃质感 Demo 并要求正式实现；随后明确要求 commit & push，并授权仅排除旧第三方验收依赖与原型备份以修正 ESLint 扫描范围。本次允许提交并推送 origin/custom，不包含额外服务器操作或修改发布配置。原型与正式实现并存；此次规则维护依据用户授权，不修改 AGENT.md。

- 原型：`about-radar-prototype/关于页雷达图-demo.html`。
- 可复现生成：`node about-radar-prototype/build-demo.mjs`。
- 长期任务：`packages/project-notes/features/about-radar.md`。

## 修改规则（必须遵守）

1. **位置与范围**：正式组件只增加在关于页「订阅新文章提醒」之前；既有作者介绍、技术栈、折腾记录、订阅入口、主题和动效不变。按用户最新尺寸要求，桌面雷达容器与原有技术栈单卡同宽（两列间距仍为 1rem），图表最大宽度 320px；窄屏自适应，保留完整九维文字与至少 44px 点击热区，不靠整块 transform 缩小字体或弹窗。Demo 是局部预览，不冒充已部署功能。
2. **九个 Title**：依用户顺序为算法、语言广度、语言深度、业务的广度、业务的深度、技术的广度、技术的深度、AI、学历。按最新反馈，轴展示 `Title(等级)`，例如 `学历(N)`；长解释仅在文档选择弹窗中展示，不在雷达标题下写宣传说明，不展示 N/Newbie 等六级图例。不能擅自减少维度、缩写 Title 或替换为条形图。
3. **等级唯一映射**：N=Newbie 灰、G=Green 绿、B=Blue 蓝、V=Violet 紫、O=Orange 橙、R=Red 红。半径顺序由内至外 N→G→B→V→O→R。按最新澄清，**不恢复初版杂色扇区，也不保留第二版纯浅灰**：内部采用统一透明冰蓝玻璃质感渐变，浅色高光与细薄反光边缘，网格透过玻璃可见，图形轮廓/数值不得因材质改变。节点与 Title 旁字母仍用六级颜色。节点增加 3.6 秒缓慢呼吸闪烁，透明度最低保持 0.58 不完全消失，光环轻微呼吸；提供关闭开关，离屏/后台暂停，系统 reduced-motion 禁用动效。全 N 也要可见、可点。仅为作者自评的序数等级，不输出综合分数、平均值或学历换算。
4. **配置来源**：当前等级只来源于同一根目录的 config.json（JSON 字符串键、字符串等级值），不能从 Markdown 文本或文件名推导。未知等级、无效 JSON 必须如实报错。**最新用户要求覆盖早期默认 N 约定**：缺失配置、缺失维度、null 或空字符串都表示“没有数据”，未配置点位于中心、维度不显示等级；完全没有数据时只显示雷达外框和一个中心黑点，没有填充区域和等级。不能把缺失自动补成 N；真实填写的 N 位于第一环。九维等级与正文由作者提供，不发布 Demo 示例或虚构经历。
5. **文件式维护**：每个维度一个同名目录，当前说明为 Index.md，历史记录为 Stage1.md、Stage2.md 等。Index 优先，Stage 文件自然排序；不能按等级重排。Stage1 为 V、Stage2 为 G 是允许的，不强制递增，也不覆盖当前等级。包名/文件名与标题映射应有明确边界，阻止路径穿越。
6. **新增配置的例外边界**：这是关于页能力雷达的专用配置，不受 about.md 中「作者介绍在组件内」限制。作者介绍与现有站点配置保持原样；仅能力等级与能力 Markdown 允许独立文件。正式根目录为仓库 `about-radar/`；`config.json` 初始 `{}`，维护说明 README 不当作能力文档。
7. **交互**：点击轴标题或节点，以真正模态弹窗列出该维度 Markdown 文件；点击文档进入对应的独立阅读页面，不在雷达下方或弹窗内展示正文。正式阅读路由为 `/about/ability/:dimension/:filename`（含 `.md` 文件名），自动 URL 编码并遵循 Router basename；Demo 的 hash 路由仅作为原型。链接可直接访问，支持浏览器返回/前进与页内返回，非法或不存在的路径显示明确空态。弹窗可通过关闭、Escape、遮罩关闭，关闭恢复原维度焦点并清除模态滚动锁。阅读页沿用 Aa、Markdown 安全净化和原文切换。返回总览不重置 config。空目录显示空态；移动与键盘有等价入口，不依赖 hover。外部文件读取失败保留当前数据；异步读取以 generation/requestId 防止迟到覆盖。
8. **文章预览一致性**：正式实现应抽取/复用文章共享正文渲染层、remarkPostBasePlugins、代码/图片/数学/Mermaid 的既有能力与 DOMPurify 净化，不复制一份简化正文解析器进 About.tsx。共享抽取保持 Post 原行为，改动需文章回归。Aa 指现有 Resume 排版及其全局 data-typography 状态，不擅自改为字号滑块。
9. **高亮契约**：必须同时支持 ===高亮===、原有 ==高亮== 和 ++下划线++，支持嵌套粗体/斜体；未成对标记、a == b、a === b、C++、转义标记、行内代码、围栏代码及 Setext 标题不应被错误转换。共享 tokenizer 已支持双/三等号；客户端、构建端与 Feed 均复用同一实现，不允许另维护原型专属高亮替换。
10. **安全与无障碍**：所有 Markdown HTML 必须净化，原文用 textContent；用户文本不拼接可执行 HTML、脚本或 SVG；外链安全属性保留。错误/动态内容 aria-live，焦点可见，弹层若采用须管理与恢复焦点，Escape 行为遵循现有阅读栈。
11. **SSG/性能**：正式版需要 Pages/cloud 都可使用的构建期清单与确定性首帧；不能把浏览器目录选择当作生产运行的数据加载。公开自评文件是否纳入搜索/Feed/sitemap须明确设计，默认不冒充普通文章。配置驱动单一模型，图形、选中等级与文件列表不得各写一套等级值；无 JS 有可读回退。
12. **验证与进度**：长期记录区分 Demo、本地实现、部署与生产验收；未完成不勾选。Demo 至少实际渲染桌面与手机，并驱动混合配色→选择维度→选择 Markdown→Aa/原文→三等号高亮主路径。正式接入后补 config/清单/tokenizer/交互/水合回归，按 AGENT 运行类型、lint、相关与共享测试及两端构建。只提交本次文件；仅在用户明确要求时 push，不改用户未要求内容。

## Demo 验收边界

原型支持文章同源 remark 语法、项目字体与 Resume 样式、代码高亮、三等号与双等号高亮，支持导入 JSON/目录与只读本地 Markdown。数学、Mermaid、文章图片放大/相对资源路径、图片完整布局、正文代码完整工具栏不属于本轮 Demo 的完整一致性验收，正式实现必须复用文章能力。原型使用 SVG，等级用节点颜色、呼吸光环与 Title 旁的字母表达，内部采用透明冰蓝玻璃质感渐变、高光与细薄反光边缘；不引入在线图表依赖。
