# 私有简历

代码与本地验证完成；生产部署和线上账号数据尚待验证。

## 使用方式

- 导航「简历」进入 `/resume`。生产沿用 `/Blog/resume`；Pages 导航跳到云端同源入口，仅 cloud 构建包含编辑器和账号 API。
- 每个账号管理一份简历，读取与编辑均要求登录，默认仅本人可见。复用账号密码与 GitHub 登录。
- 「导入」读取 `.md`、`.markdown`、`.txt` 和简历 `.json` 备份；也可在「Markdown」模式直接粘贴全文。Markdown 文件上限 1 MB、正文上限 10 万字，JSON 备份上限 2 MB。导入替换当前正文及评论，已有内容时先确认。
- 「文档编辑」可直接修改正文、标题和列表，支持加粗、斜体、下划线、撤销、重做。「预览」只读。
- 选中文字后右键提供添加评论、高亮、标红、标绿、清除颜色。键盘可用 Shift+F10 打开菜单；手机使用换行工具栏。
- 评论在桌面右侧展示，900px 以下移到正文下方；包含引用、内容、时间，支持编辑与删除。点击引用定位原文，点击正文批注标记激活评论；同一处多条批注可循环激活。
- 评论随正文保存、按账号隔离。正文选区通过持久化标记定位，支持重叠选区、跨段落和表格；前方插字不会错位，相同文字不会误定位。原文被删除或 Markdown 定位标记被移除后，评论保留并提示，不自动猜测关联。
- 每份简历最多 100 条评论，单条 2000 字，选中引用最多 1000 字；代码块和代码文字暂不支持批注。写评论期间正文更改时拒绝使用旧选区，保留未提交输入并提示重新选择。
- Markdown 是唯一正文来源。颜色、高亮、下划线和评论定位以安全内嵌 HTML 保留；复杂表格保留 HTML 结构。「导出 Markdown」仅导出正文，「备份」导出包含评论的 JSON，可通过导入完整恢复；错误与冲突恢复入口同样下载完整备份。
- 支持旧模板的 HTML 经历标题和日期；私有字体图标转换为普通文字。图片及任意脚本、样式不支持，导入时有提示。可视化编辑后的导出属于规范化文档，不保留旧模板 CSS/头像等被过滤的内容。
- 导入指定本地文件不会修改原文件，也不会持续监听原文件。原始个人内容只通过登录后的导入进入数据库，不内置到源码、静态产物或其他账号模板。
- 沿用简洁纸张排版和全站明暗主题，390px 工具栏换行。简历页隐藏会遮挡正文的看板娘与返回顶部按钮，保留账号和同步悬浮球。

## 存储与同步

- `GET /api/v1/resume`：从会话确定用户，返回本人简历快照。
- `PUT /api/v1/resume`：`expectedUserId`、`baseRevision`、`mutationId`、`state: { version: 1, markdown, comments?: [{ id, quote, body, createdAt }] }`。兼容没有 comments 字段的旧快照，沿用迁移 019，无需新增迁移。
- `expectedUserId` 仅防止跨标签页切换账号后的旧草稿误写；授权始终使用服务器会话身份。响应 `no-store`，非安全请求精确校验 Origin，不接受用户查询参数。
- 迁移 `019_resumes.sql` 创建 `resumes` 与 `resume_mutations`。账号行锁、版本检查和同一数据库事务保护并发更新；稳定回执支持网络失败后的幂等重试。
- 输入停止 800ms 后自动保存，连续输入最长 4 秒触发保存；同时只发起一个写请求。正文与评论作为一个快照原子提交，只修改评论和保存中再次修改评论也会进入下一轮保存。失败最多自动重试三次，仍可手动重试或下载草稿。
- 未确认保存的草稿按账号写入本机存储，保存成功移除；恢复后先核对版本。冲突保留本机草稿，不覆盖新云端版本，可下载草稿后明确读取云端。
- 账号变化或失效清除内存、待发请求及当前账号恢复草稿；普通刷新或导航保留未保存草稿。迟到响应不能恢复旧账号正文。手动刷新过程中发生的新编辑也不会被覆盖。
- 文档展示和粘贴均经 DOMPurify 白名单处理，禁止脚本、iframe、事件属性、危险链接与布局 CSS。
- 批注标记只允许 `span[data-resume-comments]` 中有效的 UUID，粘贴清除复制的批注定位，避免误关联旧评论。前后端均校验评论字段、数量、长度、唯一 ID 与时间格式。
