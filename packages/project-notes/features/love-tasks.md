# Love 必做清单

2026-11-07，本地实现，尚未部署到生产。

Love 面的桌面和手机导航在左侧品牌与爱心之后新增「必做」，使用与 Blog 栏目相似的文字和选中下划线。桌面与手机共用同一个入口；点击打开清单，再次点击收起。原爱心仍用于进入和退出 Love 面，原导航、页脚和手机底部导航继续在 Love 面隐藏。Love 首页默认不展开清单。

Love 背景复用 Blog/Book 的 `BookSky`，在 Layout 外壳渲染全屏天空与云层，覆盖导航区域；明暗主题分别采用日间蓝天与深蓝天空。移除原粉色渐变和网格，人名走动/雨幕特效作为低透明度的独立图层保留，效果菜单也改为天空玻璃样式。进入 Love 无论原背景选择如何都使用天空，退出后恢复原选择，不改写个人背景偏好。

清单采用“大事项 → 小任务”结构，例如「一起在深圳生活」下有「做一顿饭」「走一次公园」。大事项以较大标题展示，子任务缩进展示并独立勾选；每组完成进度由子任务计算。打开默认选中首个已保存大事项，展示该事项全部小任务，包括已完成任务；其他大事项通过「选择大事项」下拉切换，每次只展示一个，页面不包含常驻输入表单。

展示区已移除「我们一起要做的事」、大事项/小任务总数描述及顶部进度条。选择器下方直接显示筛选和添加。清单卡片采用磨砂透明玻璃：半透明天空色底、22px 背景模糊、细边框、内侧高光与柔和阴影，兼容明暗主题；添加/编辑弹窗及同步球沿用天空玻璃色调。

筛选数量只统计当前大事项，切换事项恢复“全部”筛选并收起旧删除确认。新增保存成功（包括关闭弹窗后的重试）会自动选中新事项；删除当前事项后回退到剩余首个事项，删空后展示空态。普通云端刷新保留当前有效选择。切换仅更新组件内选择状态，不请求 API、不上传选择、不建立私人 localStorage 副本；后台始终保留完整分组数据。

单独的「添加」按钮打开弹窗，填写大事项、可选备注和至少一个小任务；可连续添加子任务，每项可以记录备注。组内「编辑」和「添加小任务」也打开同一个弹窗，预填原内容并保留已有子任务的 ID、备注、创建与完成日期。移除子任务在编辑弹窗中操作；删除整个大事项需在卡片内确认，并同时删除其子任务。弹窗支持初始聚焦、Tab 焦点循环、Escape/取消/遮罩关闭、焦点还原和手机内部滚动，保存按钮固定在弹窗底部。

提供待完成、已完成、全部筛选和各组完成数量。筛选按小任务状态显示，保留对应大事项标题。日期使用北京时间，完成日期来自记录字段，渲染时不读取当前时钟。

## 登录与保存

只要求真实账号登录，不要求绑定 GitHub。未登录不读取清单，不显示任务操作控件；点击「登录后记录」打开现有云端账号面板。账号面板移至 `AppRoutes` 中与 Layout 平级，避免 Love 面替换普通内容时一并卸载账号功能。

`GET/PUT /api/v1/love/tasks` 始终从服务端会话读取账号，不接受客户端指定用户。清单按账号私有保存，没有情侣双账号共享或账号配对功能，也没有私人 localStorage 副本。退出、账号切换和组件卸载取消旧请求并丢弃迟到响应。

新增 `014_love_tasks.sql`，包含 `love_tasks` 和 `love_task_mutations`。每次保存使用用户行事务锁、版本比较、mutation UUID 和 JSONB 标准化摘要。重试保留原 mutation ID，历史成功请求重放返回最新内容，不重复添加或覆盖新版本。写入任务和幂等回执在同一事务中；回执失败会回滚任务写入。

客户端只在服务端确认成功后更新任务、完成进度并关闭编辑弹窗。失败保留当前输入，弹窗内提示未确认保存并提供重试；冲突提示读取云端版本后重新操作，重新加载会丢弃旧编辑窗口。API 响应 no-store，修改请求校验精确 Origin；字段、日期、UUID、跨组重复 ID、文本和容量均校验。

分组数据格式为 `version: 2, groups: [...]`。服务端同时接受已有 v1 平铺清单，客户端读取时确定性转换为「已记录的愿望」分组，下一次确认保存后写入 v2。旧任务 ID、备注与完成日期保持不变；每组最多 100 个小任务，旧记录较多时按原顺序分为多组，不丢弃内容。v2 最多 1000 个大事项、总计 5000 个小任务。现有 JSONB 表支持两种格式，不增加第二次数据库迁移。

云端同步从页面顶部移至独立悬浮球，沿用 Trend/Planner 的 53px 圆形、状态圆点、旋转同步图标和展开详情交互。浮球通过 portal 挂载到 body，位于账号球上方，避让安全区、Cookie 提示和更新通知；详情面板支持外部点击/Escape 关闭并恢复焦点。登录后加载成功即确认同步状态，修改后自动保存。详情展示账号、最近确认时间、立即同步/重试保存及冲突读取云端版本。手动同步仅刷新云端快照，保留当前清单和面板；失败仍展示已确认的内容，待保存操作重试保留原 mutation，账号变化拒绝迟到刷新响应。弹窗内的保存失败反馈仍保留，方便直接重试。

Pages 只展示云端登录引导，不加载清单组件、不请求账号 API；cloud 条件懒加载清单。SSG 首帧不包含私人清单或登录状态，清单展示使用 noindex。
