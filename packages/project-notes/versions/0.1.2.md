# 0.1.2 — 发文同步与云端发布

日期：2026-10-21。

## 问题

`custom` 新文章已在 GitHub Pages 发布，但云端使用 2026-10-20 的首次构建。
云端功能分支没有合入日常内容分支，首版也没有自动部署到服务器。
此外 CI 构建使用旧域名，与前端 canonical 不一致，SEO 审计失败；
Cookie 测试没有清理 sessionStorage，关闭状态影响后续测试。

## 变更

- 将云端首版与 `custom` 的 Hot 100 文章整合到同一提交链。
- CI Pages 构建使用实际 Pages URL 和 `/Blog/`，云端使用同一 canonical。
- 修复 Cookie 测试隔离并覆盖会话关闭语义，页面行为保持不变。
- 新增 `Deploy to Cloud`：同一 `custom` 提交的 CI 全部通过后下载 cloud 制品，
  串行发布；跳过已被新提交替代的构建。可在 custom 手动执行相同检查及构建。
- 发布包只包含审计过的 cloud 制品及同一提交的部署/API 源码，带文件 SHA256。
  拒绝 Pages 制品和符号链接；原始文章、temp 与本机凭据不进入包。
- 服务器严格验证 SSH 主机、公网 HTTPS、容器健康和发布提交；
  完成验收才更新 current/镜像标签。发布失败恢复旧镜像与指针，不删除数据卷。
- 镜像和 release 目录使用提交 SHA 加制品摘要，重试不会覆盖旧版本。
- 上传使用有限并行分块，完整重组并验证 SHA256 后才进入服务器发布，
  避免跨网络单连接低速拖延上线；失败不会替换已有发布包。

## 上线边界

自动部署默认关闭，需要 Actions Variable `CLOUD_DEPLOY_ENABLED=true`、
`CLOUD_SSH_PRIVATE_KEY` 和 `CLOUD_SSH_KNOWN_HOSTS` 两个 Secret。
2026-10-21 已配置 Secrets 并开启发布变量；数据库/OAuth 凭据继续仅保存在
服务器 root 0600 文件中。

代码与构建验证结果见本次部署记录。专用 SSH 公钥已授权，`1936071` 已发布，
公网新文章与 API 健康检查通过；已确认 Actions SSH 认证成功并补充分块上传，
等待下一次 CI 制品自动发布和公网提交号验收。
生产回滚演练尚未执行，回滚脚本存在不等于已完成生产演练。
数据库备份作业、网关配置变更和第二账号生产验收不在本次发布范围内。
