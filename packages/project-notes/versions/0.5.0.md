# 0.5.0 — Trend 自动同步

日期：2026-10-22。

Trend 类别、条目、坐标、阈值和 dashboard 配置通过 Go API 保存到 PostgreSQL，连接同一 GitHub 账号后可在 Pages、本地与云端同步。
修改后防抖 700ms 上传，页面可见时每 15 秒拉取，窗口聚焦、网络恢复和“立即同步”也触发同步。
本机保留账号草稿和未确认写入；版本冲突显示两个明确选项，避免直接覆盖另一端修改。

依据用户“按 Go API + PostgreSQL 方案实现自动同步”的授权，为 Trend 单独增加跨源授权与精确 CORS。
Pages 仅在 Trend 水合后加载接口模块，其他页面继续裁剪 cloud 账号能力。
云端同源使用原 Cookie；跨源通过授权弹窗和 S256 PKCE 交换一次性 code，获得绑定 origin、仅在内存保存的 1 小时 Trend token。
code 有效期 60 秒且只消费一次；token 关联原会话，退出云端账号、会话过期或主动断开会撤销授权。

新增兼容迁移 `002_trend_sync.sql`：`trend_dashboards`、`trend_connect_codes`、`trend_sessions`，以及 OAuth 的受限 `return_path`。
保留 `001_initial.sql`、用户和原会话摘要；迁移由部署流水线在新 API 启动前执行。
保存采用账号行锁、版本比较和 mutation ID 幂等重试。账号从服务端会话读取，不接受客户端 user_id。

部署需检查 `TREND_ALLOWED_ORIGINS`，默认包含 Pages origin 与 localhost:3000/3001；更换域名或开发端口需显式调整。
前端默认连接现有 `https://43.138.216.53`，自定义 API 使用构建变量 `VITE_TREND_API_ORIGIN`。
