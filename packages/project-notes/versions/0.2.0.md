# 0.2.0 — 前端 workspace 与双端部署边界

日期：2026-10-21。状态：本地结构迁移与验证，未推送、未发布到线上。API 功能、数据库 schema 与会话协议保持 0.1.0。

## 目录职责

- packages/blog：实际 React 前端、HTML、Vite/SSR、前端 TS/测试配置、依赖与命令；同时生成 pages/cloud 目标。
- packages/server：独立 API、数据库迁移与服务端集成测试，生产安装不需要 React 或前端源码。
- packages/project-notes：工程记录；根 scripts/config/public/generated 和内容目录为共用内容/构建基础设施。
- deploy/pages：静态 Pages 发布说明；deploy/cloud：服务器镜像、网关、发布与维护。
- .github/workflows：保留 GitHub 要求的工作流位置，custom 推送仍沿用现有两端发布流程。

## 迁移

前端 src、index.html 与真实 Vite/SSR/Vitest 配置进入 packages/blog；前端 package 独立声明 React、渲染、Markdown 和测试依赖。
根 package 负责工作区与共用工具编排；根 Vite 配置 re-export 前端配置，根 config/tsconfig 只 extends 前端配置。
根 Vitest 组合前端和 scripts 门禁，前端 Vitest 仅覆盖自身测试；根 typecheck/npm test 继续覆盖前后端。

原文章、配图、说说、友链、Summary、.pages.yml 和站点配置保持原位；没有建立另一份文章或 Pages React 应用。
前端数据服务同步调整 glob/懒加载路径，getPostById 使用新的 glob key，生成的 /posts/... 元数据契约保持不变。
共用无 UI 的 Markdown/加密核心通过 @d-blog/blog 的显式 package exports 引用。

客户端与 SSR 的 root 指向前端 workspace，envDir 指向仓库根；public、dist、dist-ssr 路径保持已有流水线和部署契约。
根命令经 npm 转发参数时保留 -- 分隔，避免 --host/--port 等选项被上层 npm 吞掉。
pages/cloud 目标显式选择能力后进入同一 scripts/build.mjs；Pages 构建不受外层 cloud 环境标记影响；保留根生产 env 文件和 shell 对路径、站点 URL 的配置，shell 优先。
云端打包/服务端 Docker 同步加入前端 package.json，构建 API 仍不上传或安装前端源码与 React。
