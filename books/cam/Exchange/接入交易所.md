# 对接一家交易所的流程

我们接入一个交易所 会分为 完成基建 和 接入资产 以及 接入记录 这三个步骤

## 完成基建部分

1. 主要目标是完成 交易所的 HTTP Client 内容搭建
2. 搭建完成之后 在 inner-api 提供对应的 RequestRaw 供产品那边 call 对应的接口获取资产信息 比对字段出 PRD

### 难点

Q : 早期在没有 Ai 的时候，由于其他交易所没有提供 Go 的 SDK 只有 python or JS 的 SDK 导致确定签名方式的时候较为困难

解决办法分为以下几个 :

1. 根据一些 KeyWords 例如 HMAC，SHA256 等内容，使用 Go 对应的包 double check python or JS 输出的内容
2. 也可能会出现少部分情况，就是 交易所要求的参数不明确 例如要的不是 apikey 而是某一个单独的凭证，这时候会尝试 去找交易所那边进行联调
3. 也会出现联调不上的情况，这时候我们回去 dc 上面，或者其他社区寻找对应的解决办法

## 接入资产部分

1. 根据 PRD 对接对应的 资产 和 持仓接口
2. 在对接之前 会明确 对应的 限速, 并且通过合理的 限速处理 方案 进行控制
3. 完整的对接持仓 以及 计算资产

### 难点

Q : 接口限速处理

1. 常规限速 例如 根据 Apikey 、user-id 会使用本地内存 缓存 20s 的形式进行控制限速 ，防止多个重复账户的资产录入
2. 根据 IP 限速的情况

   - 控制资产采集频率
   - 使用本地缓存 缓存所有账户的资产

3. 有一些是根据 IP + Session 进行维护限速的

   - Session 的形式维护的 需要避免重复签名的问题，即对于多个进程，我们都使用同一个 Session 进行维护

Q : 内部接口超时控制 . 持仓接口可能是一个翻页接口, 对于大持仓的 客户，预计会翻30页，导致接口超时

    - 通过 error.Group 处理并发翻页的内容

Q : 持仓和资产的 对接关系

    - 持仓接入完成之后 还需要处理一些 持仓的内容 聚合计算到 资产上

## 接入记录部分

1. 明确接口接入方式

2. 配置记录抓取方式 并且根据 PRD 对接对应的接口

### 难点

Q : 需要保证接口抓取不漏

1. 翻页抓取的时候 需要传递对应的 page，根据 len < limit 进行判断
2. offset 抓取的时候 传递对应的 offset
3. time 抓取的时候 需要传递对应的 last-time
4. 一般来说 time 抓取会漏数据，因为边界问题，因此我们一般都是 time + offset or time + page 的形式
