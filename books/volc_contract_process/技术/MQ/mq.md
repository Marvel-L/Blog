# 生产者

| 输出         | 谁产生消息                                          | 谁消费                                             | 解决的问题                                   |
| ------------ | --------------------------------------------------- | -------------------------------------------------- | -------------------------------------------- |
| 内部延迟任务 | workflow、auditx、EventBus、审批回调、contractevent | 本系统 `handlerDeferMsg`                           | 将文件生成、签约提交、提醒、事件汇总异步执行 |
| 合同业务事件 | contractevent                                       | 本系统合同事件消费者按配置接入；其他订阅方在仓库外 | 合同变化后联动履约、报价、CRM、信控等        |
| C360 提醒    | notify、审核流程、风险审核、催办模块                | C360 消费侧                                        | 销售待办、催办、合规结果提醒                 |

# 消费者

| 来源                 | 消费入口                 | 主要处理                                   |
| -------------------- | ------------------------ | ------------------------------------------ |
| OA 状态、OA 流程变化 | mqconsumer，两条入口     | 同步签署、撤回、驳回、取消、归档及合同信息 |
| 飞书合同变化         | mqconsumer               | 同步合同状态、信息和归档结果               |
| 账号实名 MQ          | mqconsumer               | 检查草稿、待确认合同的实名与主数据一致性   |
| 账号实名 InnerEB     | mqconsumer               | 对已签订未过期合同，处理企业实名变化提醒   |
| 内部延迟任务         | handlerDeferMsg          | 按消息类型调用业务模块                     |
| 合同业务事件         | handlerVolcContractEvent | 重算生效状态、同步下游、处理飞书退回联动   |
| 履约结算事件         | handlerPerformEvent      | 更新结算条款是否开始执行                   |
| 交易主数据事件       | handlerSubjectMeta       | 发送主体变化通知                           |
| Binlog 数据变化      | datamerge                | 主体补齐、结算通知、报价释放、协同数据联动 |
| Binlog 数据变化      | contractevent            | 提取变更事件，汇总后生产合同事件           |
