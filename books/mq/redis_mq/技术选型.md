# Redis 实现 MQ 的问题

## 存储

我们 MQ 需要在 ==partition== 层面保存对应的消息 一段时间

因此需要考虑 ==存储消息==

1. Redis 本身是基于内存实现的, 因此 存储消息 时容量相对有限 并且 昂贵

## 数据丢失

Redis ==不可避免== 的存在数据丢失的风险

1. 内存是 易失性存储 ; 即便 redis 中有 `rdb/aof` 之类的持久化机制 加以弥补。 但是这个持久化流程是异步执行的、无法提供百分之百的保证力度

2. Redis 走的是 AP 高可用流派, 数据的主从复制流程 是异步执行的, 主从切换时数据存在弱一致性问题 (@todo 学习集群)
