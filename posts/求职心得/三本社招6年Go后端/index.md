# 个人介绍

大家好，我是18年毕业的三本计算机专业的本科生。在个人介绍里我会大概说一下在校经历、第一段工作经历、第二段工作经历。

## 在校经历


当时我们学校即是本科中最差的三本，也几乎是三本中垫底的一所，再少几分就可以落到专科学校的那种。

所以学习氛围自然不如985，211这些学校，我大一、大二也是玩过来的，没怎么学习。

直到大三才幡然醒悟，开始为自己做 ++未来的职业规划以及恶补技术知识++，==所以当时在大三参加了师兄师姐开的Java课程（类似于黑马编程培训班之类的课程）==。

课程结束后对自己的技术信心满满，课程结束也恰逢大三暑假开始，就直接投了社招进了家外包公司。

**为什么投的社招？**

++当时对于我们学校来说投校招的氛围不是很足++（当然学习氛围也很差，大部分人都是混混日子），

大家甚至日常在学校也不会谈论到校招、社招这些话题（可能这就是三本和985、211学校的区别吧😅）。

所以当时我对校招、社招的也没什么理解，也不知道有什么不同。

再有一点我看我们学校以往的校招职位都是很low那种，我都不确定有没有IT公司的，印象中都是那些什么销售、厂工...

校招没什么好机会，再加上当时对自己技术能力的自信，于是大三暑假就开始了投社招。

**为什么去了外包公司？**

其实当时也有投其他私企和国企，可是在社招渠道还是挺在意工作经验的，再加上学历也不是很好。

即使写了课程中做的项目，对于社招渠道还是捉襟见肘，几乎都没给面试机会。

只有那家外包公司给了面试机会，最后也面过了。当时觉得自己还是蛮厉害的，但是现在回头看或许除了比在校其他三本学生技术强点之外，也许外包技术能力要求比较低吧😅。

## 第一段工作经历（外包）

严格来讲我在这家外包公司工作差不多待了四年，因为大四一整年我除了考试回去，其他时间都在公司里，大学课程都是舍友帮我举手。

**为什么外包公司也能待四年？**

当时我很少看网上的职场信息，也是因为在那四年里我感觉我每天都有在学到东西，而不是重复性的无脑工作。

我在刚入职2个月后被叫去研究当时热门的新技术（区块链），而且当时公司没人懂，只能靠自己在网上查资料学习，还要学会安排项目时间，由区块链发展历史开始学起，从0到1帮助公司落地区块链项目。

++所以四年里，我做了包括产品经理、PM、后端开发、运维这些职位的工作。++ 也参与了很多比赛拿了奖，参与了很多开源社区的聚会，尽管忙碌，但是每天都感觉充实。

**从外包裸辞**

尽管在第四年我提了加工资，也顺利给我加了。==但感觉项目已经趋于成熟，也要开始做一些重复性的工作了，加之自己想去更大的平台发展，就选择了裸辞。==

因为在外包公司很忙，比较少时间在工作的同时学习跳槽需要的知识，==再加上当时家里经济情况也允许我裸辞（我想到最坏的情况下我2-3个月没有收入也不会怎么样）==，于是就这么做了。

**裸辞后开始面试**

当时大、中、小公司都面过，印象中没人问起第一家公司是不是外包。我当时裸辞的2-3个月里有刷算法，和部分八股，但是八股只看了一点点，经不起细问（特别是MySQL八股没怎么细看）。

印象比较深的有两家：

1. 面领星，首先要做笔试题，我感觉我写的都挺好。但是 MySQL 没答好就挂了

2. 面菜鸟的时候，面试官有句话让我印象特别深：==“即使你会运维、开发还有其他的技术，即使你技术横向扩展很厉害。==但工程技术纵向不够深还是不行啊。你想想对于开发人员来说，开发能力重要还是运维能力重要。”

   当时菜鸟面试官那句话对我的打击挺大，也算是点醒了我吧。因为当时还不知道其实在大点的公司，开发与运维有专门的职位，他们都只要在各自的职位的技术栈上够深就行了（当时自己VM玩的还挺溜，其实也不是坏事啦）。
   
   不过这确实是自己的经历，也是这些经历塑造了今天我，他们不需要那就下一家吧！==面试有时候还是讲缘分的。==


## 第二段工作经历（中小厂）

当时在外包是做Java的，当时接触到区块链后对 Go 挺感兴趣，这家中小厂也接受Java转Go，就去了。

这家中小厂的规模最多人的时候应该在500-600人左右，虽然人数不及大厂，但是里面很多工作模式，和工作思想都是参考大厂的，可以说是小而美吧。

在这家公司的3年了，我也拿到了公司颁发的一些奖项，和领导的好评。

==其实第三年开始对我的成长已经不高了==，然后我一直都想去大厂看看世面，==再加上第三年绩效有个C的指标要给我背==，就加速了我跳槽的进度。

# 面试经历

刚开始面试会比较结巴，然后语言也不够精简，给面试官的体验就不是很好。

有面试官在我反问不足的时候也直接说我的回答有时间很啰嗦，不够简练。

不过随着面试多起来，以及我每次都会反问我的不足并克服它，后面就越来越顺利了。

比如有两个印象比较深的场景：

| 场景 | 克服前                                                                                                                              | 克服后 |
| --- |----------------------------------------------------------------------------------------------------------------------------------| - |
|  面试官：说一件你最自豪的事情吧。我：....（参考克服前的话）。说到一半，面试官：停停停！说这么多，其实不就是...（面试官就帮我总结了我的话）。 | 我将编译微服所用的内存减少70%，时间减少30%。具体是我先在stackoverflow找出了，然后通过分析之后得出了一份数据，然后再通过 分析了go在编译中实际执行的步骤，然后....（本来想继续说下去，把我实际做的细节全部说出来，但是就被面试官叫停了） | 面试官帮我总结成了：“我通过自己在网上查找资料，找到了分析工具及其使用方式，然后通过工具产生的数据优化了微服的依赖包。”其实实际上分析过程是挺耗时耗力的，所以我想把细节尽量说全，来表达这个过程的简单程度，也想秀一波我的思考过程。可是对于面试官来说听起来就很绕，所以如果他有兴趣继续追问，才去说更多细节。如果他本身就对你这个不感兴趣，那反而直接说细节会起到反作用。 |
| 面试官让我介绍简历第一个项目 | 我按照项目背景、业务流程、重难点的顺序来介绍。关于业务流程我说的太详细了，以至于业务流程说完之后，面试官也是有点懵。在最后也是建议我其实对于业务规则可以简练一点，因为与面试业务不一样，面试官他也不是很关心我上家公司具体业务                  |  原来项目介绍内容比例大概是这么划分：项目背景（20%），业务流程（30%），重难点（50%）后来我自己调整为：项目背景（10%），业务流程（10%），重难点（80%） |


投了很多，很多也没给面试机会的，包括阿里和字节都没有面试机会，是比较可惜。我都是在BOSS上投的，另外BAT我在官网上也投了一份。

关于投递 `回复率` 和 `约面率` ：我感觉对于中小厂来说投给HR和开发都差不多；

但是如果大厂投给HR就比较低了（虽感觉是学历+过往经历的原因），如果能直接投到开发甚至是组长就会高一些。
