# 现状

我们系统现在支持 `Book`、`Mind`、`Anki`、`定稿`（原 `Resume`）。

我目前的使用思路是 通过 `Book` 记录 完整技术方案 和 需求背景信息 ， 同时还会引出一些问题

使用 `Mind` 可以说又重新整理了一下 Book 不过这次是把一些问题 和 解决方案 给列出来了， 不过大体上和 Book 高度重合

`Anki` 现在是单独列出来使用的，会把项目中遇到的一些问题单独拆分到 `Anki` 中

`定稿` 按名称管理多份文档，不额外设置分类；可保存简历、面试主稿或其他内容，每份独立编辑和预览。

# 预计更改内容

`Books` 补充更加完善的内容，并且仅记录 当初遇到的问题 以及解决的方案，技术选型可以单独在 Books 列一个 文章进行列出

`Books` 中涉及的一些引出问题，可以考虑单独放到文章最下面单独列一个 Title 例如 ==面试要点== 然后 link 到我们的 `Mind` 

`Mind` 主要用于记录 面试中的问题 和 解决方案 . 不过 Mind 不适合存储图片 以及 大量文本信息，因此 Mind 只做快问快答的形式 

`Mind` 可以链接到具体定稿。`定稿` 可以保存完整答案、图片链接和来源信息，并引用 `Book` 与 `Mind`；已有完整答案优先引用。

`Anki` 保持原有的职责不变

最终使用思路

1. Book 可以过一遍完整的现有逻辑框架
2. Mind 寻找对应的问题
3. 定稿过一遍全部链路的面试方案
4. Anki 背诵一些抽离出来的点

# Ai 如何提速 ？

Ai 可以整理 Books 中的内容，给现有技术架构画图，同时抽离出现有系统的问题，并且抽离一些 问题到 Anki 中

Mind 根据整理出来的问题，补充到 Mind 中，然后用户尝试给出答案 Ai 进行 Check 

AI 整合一版 Book 和 Mind 中的内容补充到定稿中，用户核对后修改。当前可通过 Markdown 导入整理结果；自动跨模块整合与核对仍属于后续计划。

# Ai Generate

整体方向对，但**这版仍可能让你每次复习都跑遍四个入口，重新产生重复劳动。**建议调整下面五点。

1. **区分“整理材料”和“日常复习”。**

   前面的「最终使用思路」适合作为首次整理顺序，日常不需要每次从 Book 开始。

   建议写成：**面试前以主稿 / PDF 为入口；讲不清时查 Books；用 Mind 盲答检查遗漏；答不出的独立问题进入 Anki。**

2. **Mind 中“解决方案”的范围需要限制。**

   Mind 同时保存问题和完整解决方案，仍然可能让你维护另一份完整答案。建议明确：Mind 保存问题、回答关键词和来源链接，完整论证放在主稿。

   例如节点写“入库成功但入队失败？→ 补偿时效 / 重复投递 / 幂等”，不用再贴整个方案。Mind 检查项目理解的覆盖面，Anki 练习具体知识点的记忆。

3. **Books 不宜“仅记录问题和解决方案”。**

   「仅记录问题和解决方案」容易把业务约束、正常流程和实现依据删掉，而这些恰好解释了为什么采用某个方案。

   建议保留：**业务背景、真实实现、当时的取舍、异常边界和代码依据。**与项目强相关的技术选型放在对应章节；能跨项目复用的比较，再单独成文。

4. **补上“主稿与 PDF”的关系，并区分当前能力和计划能力。**

   手册遗漏了最初最重要的目标：**只维护一份主稿，PDF 从主稿导出。**

   定稿现已支持 HTTP / HTTPS 图片链接，并从当前主稿打开打印预览，选择「另存为 PDF」。图片需使用可访问链接，本地图片上传仍是计划能力。PDF 不包含评论。

   简历和面试主稿各自保存为独立文档；每个账号最多 50 份。原有单份简历保留为「我的简历」，不要把完整面试方案覆盖进简历。

5. **AI 的 Check 要有具体标准，Anki 不必提前批量生成。**

   「AI 提速」部分建议补充：答案是否符合代码与文档，是否区分已实现和改进建议，是否说明取舍与故障边界，个人贡献和结果是否有依据。

   卡片先从实际盲答中产生：用户回答 → AI 核对 → 修正主稿 → 仍答不出的题进入 Anki。这样比先抽出大量卡片更符合你减少无效整理的目标。

这份手册最值得加上的一句规则是：

> **每个载体必须有明确用途；已有完整答案优先引用。新增整理应解决一个讲不清或答不出的问题。**

## 定稿的实际使用

1. 在「定稿」中新建文档，命名为项目面试主稿，可选「填入面试提纲」；简历继续单独保留。新建默认空白，不必选择分类。
2. 用 Markdown 导入或直接编辑正文，补充主流程、个人贡献、选型取舍、异常恢复和完整讲述。整理过程只维护这份主稿。
3. 插入 Book、Mind 的来源链接；具体定稿可通过「复制链接」获得入口，打开时仍需登录同一账号。
4. 选中文字添加评论、高亮、标红或标绿，手动核对并修改内容。定稿与评论随账号自动保存。
5. 使用「预览」检查全文；全站 Aa 排版开关同时影响编辑正文与预览。需要离线复习时，从主稿打印为 PDF。
6. 「导出 Markdown」导出当前正文；「备份全部」保留全部定稿与评论。导入集合备份时新增副本，原有内容保留。

日常复习以主稿或 PDF 为入口：讲不清时查 Book，用 Mind 盲答检查遗漏，修正主稿，仍答不出的独立问题再进入 Anki。
