# 238. 除了自身以外数组的乘积

题目链接：[238. 除了自身以外数组的乘积](https://leetcode.cn/problems/product-of-array-except-self/)

参考题解：[灵茶山艾府：前后缀分解，附题单！](https://leetcode.cn/problems/product-of-array-except-self/solutions/2783788/qian-hou-zhui-fen-jie-fu-ti-dan-pythonja-86r1/)

## 题目

给定整数数组 `nums`，返回数组 `answer`，其中 `answer[i]` 等于 `nums` 中除了 `nums[i]` 以外，其余所有元素的乘积。

要求时间复杂度为 $O(n)$，并且不能使用除法。进阶要求只使用 $O(1)$ 的额外空间，==返回的答案数组不计入额外空间==。

```text
输入：nums = [1, 2, 3, 4]
输出：answer = [24, 12, 8, 6]

输入：nums = [-1, 1, 0, -3, 3]
输出：answer = [0, 0, 9, 0, 0]
```

## 难点

1. ==不能使用除法==
2. 对每个位置重新遍历其余元素，需要 $O(n^2)$ 时间，必须复用已经算出的乘积。
3. 前缀和后缀都要==排除当前位置==，注意递推时的下标与更新顺序。


## 错误的思路

1. 一开始是尝试 从质因数分解那边做，因为一个 Sum 的话，如果做了质因数分解，那么其指数就是减法而不是除法

2. 但是写的时候发现，==质因数分解本身就涉及到除法== 因此不适合做

## 思路：把自身左右两边拆开

令 $n$ 为数组长度。对于下标 $i$，除自身以外的元素可以分成两部分：

- 左边：`nums[0]` 到 `nums[i-1]`。
- 右边：`nums[i+1]` 到 `nums[n-1]`。

因此：

$$
\mathrm{answer}[i]
=
\underbrace{\left(\prod_{j=0}^{i-1}\mathrm{nums}[j]\right)}_{\text{左侧元素的乘积}}
\cdot
\underbrace{\left(\prod_{j=i+1}^{n-1}\mathrm{nums}[j]\right)}_{\text{右侧元素的乘积}}
$$

其中 $\prod$ 表示连乘，类似于 $\sum$ 表示求和。

以 `nums = [1, 2, 3, 4]`、`i = 2` 为例：

```text
下标：       0   1   2   3
nums：      [1,  2,  3,  4]
             左侧   自身  右侧

左侧乘积 = 1 × 2 = 2
右侧乘积 = 4
answer[2] = 2 × 4 = 8
```

==不需要把 `nums[i]` 乘进去，再想办法去掉它；直接组合左右两侧的乘积即可。==

## 一、前缀数组 + 后缀数组

### 1. 定义

沿用参考题解的定义，`pre[i]` 和 `suf[i]` 都不包含 `nums[i]`：

$$
\begin{aligned}
\mathrm{pre}[i] &= \prod_{j=0}^{i-1}\mathrm{nums}[j] \\
\mathrm{suf}[i] &= \prod_{j=i+1}^{n-1}\mathrm{nums}[j]
\end{aligned}
$$

首元素左侧、尾元素右侧都没有元素。规定==空乘积为 $1$==，于是初始值为：

$$
\mathrm{pre}[0] = 1,\qquad \mathrm{suf}[n-1] = 1
$$

这里使用 $1$，因为 $1 \cdot x = x$，不会影响另一侧的乘积。如果初始化成 `0`，后续乘积就都会变成 `0`。

### 2. 递推

`pre[i-1]` 已经包含 `nums[0]` 到 `nums[i-2]`，再乘上 `nums[i-1]`，就得到 `pre[i]`：

$$
\mathrm{pre}[i]
= \mathrm{pre}[i-1]\cdot\mathrm{nums}[i-1],
\qquad 1 \le i < n
$$

因此，前缀数组需要==从左往右==计算。

同理，`suf[i+1]` 包含 `nums[i+2]` 到 `nums[n-1]`，再乘上 `nums[i+1]`，得到 `suf[i]`：

$$
\mathrm{suf}[i]
= \mathrm{suf}[i+1]\cdot\mathrm{nums}[i+1],
\qquad 0 \le i < n-1
$$

后缀数组需要==从右往左==计算。

最后组合左右两侧：

$$
\boxed{\mathrm{answer}[i] = \mathrm{pre}[i]\cdot\mathrm{suf}[i]}
$$

### 3. 示例

对于 `nums = [1, 2, 3, 4]`：

| 下标 $i$ | `nums[i]` | `pre[i]`：左侧乘积 | `suf[i]`：右侧乘积 | `answer[i]` |
| --- | --- | --- | --- | --- |
| 0 | 1 | 1（空乘积） | $2 \cdot 3 \cdot 4 = 24$ | 24 |
| 1 | 2 | 1 | $3 \cdot 4 = 12$ | 12 |
| 2 | 3 | $1 \cdot 2 = 2$ | 4 | 8 |
| 3 | 4 | $1 \cdot 2 \cdot 3 = 6$ | 1（空乘积） | 6 |

```text
nums   = [1,  2,  3,  4]
pre    = [1,  1,  2,  6]
suf    = [24, 12, 4,  1]
answer = [24, 12, 8,  6]
```

### 4. Go 实现

```go
func productExceptSelfWithArrays(nums []int) []int {
    n := len(nums)
    answer := make([]int, n)
    if n == 0 {
        return answer
    }

    pre := make([]int, n)
    pre[0] = 1
    for i := 1; i < n; i++ {
        pre[i] = pre[i-1] * nums[i-1]
    }

    suf := make([]int, n)
    suf[n-1] = 1
    for i := n - 2; i >= 0; i-- {
        suf[i] = suf[i+1] * nums[i+1]
    }

    for i := 0; i < n; i++ {
        answer[i] = pre[i] * suf[i]
    }
    return answer
}
```

- 时间复杂度：$O(n)$。计算前缀、后缀和答案，各遍历一次。
- 额外空间复杂度：$O(n)$。即使不计答案数组，仍需要 `pre` 和 `suf` 两个辅助数组。

## 二、优化：复用后缀数组，只保留一个前缀变量

参考题解的优化顺序是：==先保存所有后缀乘积，再从左往右计算前缀并写入答案==。

从左往右遍历时，计算当前前缀只依赖上一个前缀，不需要保留整个 `pre` 数组。用一个变量 `pre` 滚动维护即可。

同时，后缀数组可以直接作为答案数组：处理到下标 `i` 时，把其中的后缀乘积乘上 `pre`，就得到最终答案。此后不会再读取这个位置原来的后缀值，因此可以覆盖。

### 1. Go 实现

```go
func productExceptSelf(nums []int) []int {
    n := len(nums)
    answer := make([]int, n)
    if n == 0 {
        return answer
    }

    // 第一次遍历：answer[i] 暂时保存 i 右侧的乘积。
    answer[n-1] = 1
    for i := n - 2; i >= 0; i-- {
        answer[i] = answer[i+1] * nums[i+1]
    }

    // 第二次遍历：用当前左侧乘积补全答案。
    pre := 1
    for i, x := range nums {
        answer[i] *= pre
        pre *= x
    }
    return answer
}
```

### 2. 为什么先计算答案，再更新 pre？

在第二次遍历中，==每轮开始时，`pre` 表示当前元素左侧的乘积，不包含当前元素==：

$$
\mathrm{pre} = \prod_{j=0}^{i-1}\mathrm{nums}[j]
$$

此时 `answer[i]` 仍然保存右侧乘积，所以先执行：

```go
answer[i] *= pre
```

得到：

$$
\mathrm{answer}[i]
=
\left(\prod_{j=0}^{i-1}\mathrm{nums}[j]\right)
\cdot
\left(\prod_{j=i+1}^{n-1}\mathrm{nums}[j]\right)
$$

然后执行 `pre *= nums[i]`，让前缀变成：

$$
\mathrm{pre} = \prod_{j=0}^{i}\mathrm{nums}[j]
$$

它正好是下一轮下标 $i+1$ 所需要的左侧乘积。

如果把两行顺序交换，计算答案时 `pre` 就包含了 `nums[i]`，违反“除了自身”的要求。

### 3. 逐步推演

第一次遍历结束后：

```text
nums   = [1,  2,  3,  4]
answer = [24, 12, 4,  1]  // 此时仅保存后缀乘积
pre    = 1
```

第二次遍历：

| 下标 $i$ | 当前元素 `x` | 本轮开始的 `pre` | 写入的答案 | 更新后的 `pre` |
| --- | --- | --- | --- | --- |
| 0 | 1 | 1 | $24 \cdot 1 = 24$ | $1 \cdot 1 = 1$ |
| 1 | 2 | 1 | $12 \cdot 1 = 12$ | $1 \cdot 2 = 2$ |
| 2 | 3 | 2 | $4 \cdot 2 = 8$ | $2 \cdot 3 = 6$ |
| 3 | 4 | 6 | $1 \cdot 6 = 6$ | $6 \cdot 4 = 24$ |

最后得到 `answer = [24, 12, 8, 6]`。最后一轮更新后的 `pre` 不会再被使用。

### 4. 复杂度

- 时间复杂度：$O(n)$。共两次遍历，比优化前少一次。
- 额外空间复杂度：$O(1)$。除返回数组外，只使用固定数量的变量。
- 如果把返回数组也算入，总空间仍是 $O(n)$。这里的 $O(1)$ 指题目约定的额外空间。

## 易错点与边界情况

### 1. Go 的 make 不会自动填充 1

`make([]int, n)` 创建的切片默认元素是 `0`。因此必须设置：

```go
pre[0] = 1
suf[n-1] = 1
```

优化版对应 `answer[n-1] = 1` 和 `pre := 1`。其余位置会按递推公式赋值，不需要全部初始化成 `1`。

### 2. 前后缀的定义不能混用

本文的 `pre[i]`、`suf[i]` 都排除 `nums[i]`，因此递推时分别乘 `nums[i-1]`、`nums[i+1]`，答案直接用 `pre[i] * suf[i]`。

如果采用“前缀包含当前位置”等其他定义，递推式和答案下标也必须随之调整。

### 3. 含 0 或负数时无需特殊分支

| 情况 | 结果或原因 |
| --- | --- |
| 没有 `0` | 正常组合左右两侧乘积 |
| 恰好一个 `0` | 只有 `0` 所在位置的答案可能非零，其余位置都包含这个 `0` |
| 至少两个 `0` | 排除任意一个元素后仍包含 `0`，所有答案都为 `0` |
| 包含负数 | 正负号随乘法自然计算，不需要额外处理 |
| 两个元素 `[a, b]` | 返回 `[b, a]`，空的一侧由乘法单位元 `1` 补齐 |

例如 `nums = [-1, 1, 0, -3, 3]`，下标 `2` 对应的答案为：

$$
\mathrm{answer}[2]
= (-1)\cdot 1\cdot(-3)\cdot 3
= 9
$$

其他位置排除自身后仍包含 `0`，答案均为 `0`。

题目保证数组长度至少为 `2`；代码中的空数组判断用于避免通用调用时访问 `answer[n-1]` 越界。
